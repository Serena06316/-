# 本地题库 · 刷题

一个纯静态、可部署到 GitHub Pages 的本地题库管理与刷题 Web 应用。数据全部保存在浏览器 IndexedDB 中，无需后端、无需登录、无需安装任何开发环境。

## 功能概览

- **两级结构**：文件夹（课程）→ 题集（章节/文件）→ 题目，任意创建、重命名、删除（删除前确认）。
- **内置公共题库**：把题库文件放进仓库 `question-banks/<科目>/<题集>.json`，部署后所有人可见（首页「我的文件夹」下方独立展示）；按需下载缓存，支持手动同步更新；GitHub Action 自动维护清单。
- **三种练习模式**：刷题（即点即判，答对自动下一题，答错停留看解析）、做题（选完提交的经典模式）、背题（直接看答案与解析）；题集页可选、练习中可随时切换，选择会被记住。
- **题库导入**：支持 JSON / TXT / CSV / DOCX；文件选择器、拖拽、粘贴、多文件批量导入；导入前逐题校验，失败给出原因，不影响已有数据；同名题集可选择“自动改名新建 / 合并去重 / 跳过”。
- **动态选项**：选项数量不固定（2 个、5 个、6 个或更多），自动适配；支持单选、多选、判断，可扩展。
- **刷题**：单个题集 / 整个文件夹 / 错题本 / 收藏夹四种范围（含内置公共题库）；顺序、随机；按题型、章节、仅错题、仅收藏、仅未答筛选；提交判题、答案与解析、上一题/下一题/跳过/重做；答题卡跳转；进度自动保存与恢复。
- **错题本**：自动记录，跨题集查看，按文件夹/题集/掌握状态筛选，专项刷错题，重答对 2 次标记“已掌握”，可移除或批量清理；记录作答次数、正确次数、最近作答时间。
- **收藏夹**：跨题集查看与筛选，专项刷收藏。
- **统计**：全局/文件夹/题集/每题统计（已答、答对、错题、正确率、作答次数等），全部基于真实数据计算。
- **备份与恢复**：导出全部数据、单个文件夹、单个题集为 JSON；导入备份自动区分“完整恢复（替换）”与“增量导入（不覆盖）”；恢复在事务中完成。
- **日间/夜间主题**：跟随系统并支持手动切换（选择会记住）。
- **响应式**：适配手机、平板、电脑。

## 部署到 GitHub Pages

### 方式一：网页上传（无需安装任何工具）

1. 注册并登录 GitHub，点击右上角 **+** → **New repository**。
2. 仓库名随意（如 `tiku`），选择 **Public**，点击 **Create repository**。
3. 在新仓库页面点击 **uploading an existing file**（上传文件）。
4. 将本项目目录下的**全部文件**（index.html、css、js、docs 等，保持目录结构）拖入上传区，点击 **Commit changes**。
5. 进入仓库 **Settings** → 左侧 **Pages**：
   - Source 选择 **Deploy from a branch**；
   - Branch 选择 **main**，目录选择 **/ (root)**，点击 **Save**。
6. 等待 1-2 分钟后刷新页面，顶部会出现访问地址：
   `https://<你的用户名>.github.io/<仓库名>/`

以后更新题库或修改：重复第 4 步上传/覆盖文件即可。

### 方式二：Git 命令行

```bash
cd tiku-app
git init
git add .
git commit -m "init: 本地题库刷题应用"
git branch -M main
git remote add origin https://github.com/<你的用户名>/tiku.git
git push -u origin main
```

然后按方式一第 5 步开启 Pages。

> **更新到新版本**：把新版应用文件（index.html、css、js、question-banks、.github、tools 等）上传覆盖到仓库对应位置即可；用户浏览器中的 IndexedDB 数据不受影响，无需重新导入。

> 本应用使用哈希路由（`#/...`），部署在仓库子路径（如 `/tiku/`）下也无需任何额外配置。

### 本地运行（可选）

纯静态文件，直接双击 `index.html` 在部分浏览器（如 Chrome 的 file:// 协议）可能无法使用 IndexedDB。推荐用任意静态服务器运行：

```bash
# 进入项目目录后任选其一：
python3 -m http.server 8000      # 访问 http://localhost:8000
npx serve .                      # 需要 Node.js（仅本地测试需要，部署不需要）
```

## 题库导入说明

完整格式说明请部署后打开应用内右上角 **使用说明**，或在导入遇到问题时查看。要点：

- **JSON（推荐）**：根节点为 `{"title": "题集名", "questions": [...]}` 或直接为题目数组。每题包含 `id / type / question / options / answer / explanation / chapter`；`options` 数量任意；`answer` 统一为数组（如 `["B"]`、`["A","D"]`）。
- **TXT**：`# 题集名称:` 开头；每题用 `---` 分隔；选项行 `A. 文本`；`答案: B` / `答案: ABD` / `答案: 正确`；`解析:` 与 `[章节]`、`[类型]` 可选。
- **CSV**：表头 `题干,题型,A,B,C,...,答案,解析,章节`，选项列数量任意，含逗号字段加英文双引号。
- **DOCX**：按 TXT 规则排版即可（`---` 分隔、`答案:` 等）；仅支持 .docx，不支持旧版 .doc；需要较新浏览器（见兼容性）。
- 示例文件见 `docs/samples/`，可直接导入体验。

**重复导入**：目标文件夹已存在同名题集时会询问——自动改名新建 / 合并（题干+选项+答案完全相同的题目自动跳过）/ 跳过，不会默认覆盖，不会产生重复题目。

## 内置公共题库（维护者功能）

把题库文件放进仓库的 `question-banks/<科目>/<题集>.json`，部署后**所有访问者**都会在首页下方看到「内置公共题库」：

- **文件夹名 = 科目名，文件名 = 题集名**，支持中文；支持 **.json（推荐）/ .txt / .csv / .docx**（UTF-8，格式同「题库导入说明」）；**文件夹必须至少包含一个题库文件才会显示**（GitHub 不保留空文件夹）。
- **无需维护任何清单**：没有 `question-banks/manifest.json` 时，应用会自动调用 GitHub 接口扫描仓库目录发现题库（仅 `*.github.io` 部署时自动识别仓库；自定义域名需在 `js/public.js` 顶部 `REPO_OVERRIDE` 填入「用户名/仓库名」）。
- 网络访问 GitHub 接口不稳定时，可改为清单方式：上传 `manifest.json`（格式见 `question-banks/README.md`，可手动维护或用 `.github/workflows/update-banks.yml` Action 自动生成）。清单存在时优先使用清单。
- 上传 / 修改文件后等 **1-2 分钟**（GitHub Pages 更新），访问者点首页「刷新」即可看到。
- 想把 Word 题库发布为公共题库：先在应用内导入（自动转换），再到题集页点「导出题库 JSON」，把导出的文件上传到 `question-banks/` 即可。

## 数据备份与恢复

- 应用内右上角 **数据库图标 → 备份与数据管理**：
  - **导出全部数据**：一个 JSON 文件，包含文件夹、题集、题目、答题记录、错题、收藏、练习进度。
  - **导出单个文件夹 / 单个题集**：也可在对应页面操作。
  - **导入备份**：自动识别备份类型。完整备份会先确认再**替换**全部现有数据（在单个数据库事务中完成，避免写坏）；文件夹/题集备份作为**新内容添加**（自动重映射 ID，不影响现有数据）。
- 普通题库导入与备份恢复严格区分：导入题库不会覆盖答题记录、收藏或错题。
- 备份 JSON 可跨设备：在新设备打开应用 → 数据管理 → 导入备份。

## 数据存储与隐私

- 所有数据保存在**当前浏览器**为本站点分配的 IndexedDB 中，不上传任何服务器、不联网同步。
- 刷新、关闭网页、重新打开浏览器后数据仍在。
- 但换设备、换浏览器、清除浏览器站点数据（或无痕模式）都会导致数据不可见或丢失——请定期导出备份。

## 兼容性

- 现代浏览器：Chrome / Edge 80+、Firefox 90+、Safari 14+（桌面与移动端）。IndexedDB 为必需能力。
- DOCX 解析依赖 `DecompressionStream`：Chrome/Edge 80+、Firefox 113+、Safari 16.4+；不满足时应用会给出明确提示，请改用 JSON/TXT/CSV。
- 需要 JavaScript（纯前端应用，无任何后端）。

## 技术说明

- 原生 HTML/CSS/JS，无框架、无构建步骤、无外部依赖；全部代码可在上述目录结构中直接阅读。
- IndexedDB 结构（库名 `tiku-db`，版本 2）：`folders / sets / questions / records / mistakes / favorites / sessions` 七个对象仓库，均建有索引；v2 为 folders/sets/questions 增加 `by-origin` 索引以区分用户自建内容与内置公共题库；升级机制见 `js/db.js` 中 `createSchema`。
- 判题逻辑：单选与判断题要求所选与答案（标签集合）一致；多选题按“选项集合”判等，与选择顺序无关；提交后锁定防止重复计分，“重做”保留历史记录并计入尝试次数。
